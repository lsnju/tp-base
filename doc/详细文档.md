# tp-base 详细文档

## 1. 文档说明与适用范围

- 本文档定位为 `tp-base` 基础库/框架能力交付文档，用于新项目接入、存量治理、团队规范统一，不讨论具体业务领域建模。  
  （证据：`pom.xml`、`README.md`）
- 代码库是多模块 Maven 聚合工程，核心模块围绕 Web 基础能力、模型/响应约定、日志、配置与工具类展开。  
  （证据：`pom.xml`）
- 文档所有结论均以仓库源码为准；未在仓库中出现的内容，统一标注为 `代码中未发现`。  
  （证据：全仓库检索结果）
- 关于“自动装配”本仓库采用注解 + `@Import` 显式装配，不是 Spring Boot Starter 常见的 `AutoConfiguration.imports`
  自动发现模式。  
  （证据：`tp-base/src/main/java/com/lsnju/tpbase/annotation/EnableTpBase.java`、
  `tp-base/src/main/java/com/lsnju/tpbase/annotation/EnableTpBaseConfig.java`、全仓库
  `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 检索为空）

## 2. 架构概览

- 框架核心入口是 `@EnableTpBase`，它聚合了基础配置、过滤器、Profiler、Digest AOP、全局异常处理。  
  （证据：`tp-base/src/main/java/com/lsnju/tpbase/annotation/EnableTpBase.java`）
- `@EnableTpBaseConfig` 最终导入 `TpBaseAutoConfiguration`，后者再通过 `@Import` 引入 MVC helper、SpringFox 适配、Jackson
  Money 序列化、线程池、Filter 配置展示等。  
  （证据：`tp-base/src/main/java/com/lsnju/tpbase/annotation/EnableTpBaseConfig.java`、
  `tp-base/src/main/java/com/lsnju/tpbase/autoconfigure/TpBaseAutoConfiguration.java`、
  `tp-base/src/main/java/com/lsnju/tpbase/autoconfigure/TpBaseConfiguration.java`）
- Web 入口链条按 Servlet Filter + Spring MVC + AOP + `RestControllerAdvice` + `BaseResp`
  组织，具备请求上下文、性能日志、统一异常返回能力。  
  （证据：`tp-base/src/main/java/com/lsnju/tpbase/autoconfigure/TpServletFilterConfiguration.java`、
  `tp-base/src/main/java/com/lsnju/tpbase/autoconfigure/TpRestApiLogConfiguration.java`、
  `tp-base/src/main/java/com/lsnju/tpbase/autoconfigure/TpExceptionHandler.java`、
  `tp-rs-simple/src/main/java/com/lsnju/base/model/rs/BaseResp.java`）
- 版本基线：Java 17、Spring Boot 3.5.15（父 POM 为 `spring-boot-dependencies`）。  
  （证据：`pom.xml`）
- Maven 最低版本要求：`代码中未发现`（未见 `maven-enforcer-plugin` 或显式 `maven` 版本下限）。

## 3. 模块职责与依赖关系

- 聚合模块清单（顶层）：`tp-utils`、`tp-domain-*`、`tp-rs-*`、`tp-model`、`tp-base-config`、`tp-base-log`、`tp-base-log4j2`、
  `tp-base`、`tp-bom`。  
  （证据：`pom.xml`）
- `tp-bom`/`tp-base-dependencies` 负责统一版本管理，业务项目应优先通过 BOM 导入而非手写版本。  
  （证据：`tp-bom/pom.xml`、`tp-base-dependencies/pom.xml`、`README.md`）
- `tp-base` 是框架装配核心，依赖 `tp-utils`、`tp-model`、`tp-base-config`、`tp-base-log`。  
  （证据：`tp-base/pom.xml`）
- `tp-model` 当前默认选型是 `tp-domain-gson + tp-rs-simple`，意味着引入 `tp-base` 时会间接采用该实现。  
  （证据：`tp-model/pom.xml`）
- `tp-base-config` 提供标准化 `application*.properties` 模板，包含管理端点、数据库、mybatis、json、日志、任务等默认键。  
  （证据：`tp-base-config/src/main/resources/application.properties`、`tp-base-config/pom.xml`）
- `tp-base-log` 与 `tp-base-log4j2` 分别承载 logback/log4j2 侧日志能力。  
  （证据：`tp-base-log/pom.xml`、`tp-base-log4j2/pom.xml`）

### 同名类多模块互斥与选型（必须关注）

- `tp-domain-default/short/json/gson/jackson/jackson-mask` 都定义同一 FQCN：`com.lsnju.base.model.BaseMo`，仅 `toString()`
  策略不同，因此不可同时入同一应用类路径。  
  （证据：各模块 `src/main/java/com/lsnju/base/model/BaseMo.java`）
- `tp-rs-default` 与 `tp-rs-simple` 均定义同名包类（`BaseResp`、`RespEntityUtils` 等），同样应二选一。  
  （证据：`tp-rs-default/src/main/java/com/lsnju/base/model/rs/BaseResp.java`、
  `tp-rs-simple/src/main/java/com/lsnju/base/model/rs/BaseResp.java`、两模块文件清单）
- `tp-rs-*` 依赖 `tp-domain-multi` 为 `provided`，实际运行期应由宿主项目提供唯一 domain 实现。  
  （证据：`tp-rs-default/pom.xml`、`tp-rs-simple/pom.xml`）
- 框架内未见“冲突检测器”自动阻止多实现并存，冲突主要由构建/运行期类重复触发。  
  （证据：全仓库检索未见冲突治理组件，`代码中未发现`）

## 4. 核心运行链路

- Filter 层：按 `FilterOrderConstants` + `FilterRegistrationBean` 注册，包含日志 MDC、请求上下文、性能日志、Header
  日志、用户上下文等。  
  （证据：`tp-base/src/main/java/com/lsnju/tpbase/config/FilterOrderConstants.java`、
  `tp-base/src/main/java/com/lsnju/tpbase/autoconfigure/TpServletFilterConfiguration.java`）
- MVC 层：`TpSpringWebMvcHelper` 封装 `HandlerExceptionResolver` 与 serverUrl 推导。  
  （证据：`tp-base/src/main/java/com/lsnju/tpbase/autoconfigure/TpBaseConfiguration.java`、
  `tp-base/src/main/java/com/lsnju/tpbase/web/mvc/TpSpringWebMvcHelper.java`）
- AOP 层分两类：
    1) Digest AOP（DAO/SAL BeanName 代理）由 `@EnableDigestConfig` 默认包含；
    2) REST 入参出参日志切面需显式启用 `@EnableTpRestApiLog`。  
       （证据：`tp-base/src/main/java/com/lsnju/tpbase/annotation/EnableTpBase.java`、
       `tp-base/src/main/java/com/lsnju/tpbase/annotation/EnableDigestConfig.java`、
       `tp-base/src/main/java/com/lsnju/tpbase/annotation/EnableTpRestApiLog.java`、
       `tp-base/src/main/java/com/lsnju/tpbase/autoconfigure/TpRestApiLogConfiguration.java`）
- ExceptionHandler 层：`TpExceptionAutoConfiguration` 导入 4 组 `RestControllerAdvice`，覆盖 Web 参数异常、校验异常、DAO
  唯一键异常、兜底异常。  
  （证据：`tp-base/src/main/java/com/lsnju/tpbase/autoconfigure/TpExceptionAutoConfiguration.java`、
  `tp-base/src/main/java/com/lsnju/tpbase/autoconfigure/TpExceptionHandler.java`）
- Resp 层：统一通过 `RespEntityUtils` 返回 `ResponseEntity<BaseResp<T>>`，错误码来自 `BizErrorEnum`，并写入 `TpRestContext`
  供摘要日志消费。  
  （证据：`tp-rs-simple/src/main/java/com/lsnju/base/model/rs/RespEntityUtils.java`、
  `tp-rs-simple/src/main/java/com/lsnju/base/model/rs/BaseResp.java`、
  `tp-base/src/main/java/com/lsnju/tpbase/web/filter/rest/TpRestApiDigestFilter.java`）

## 5. 配置体系与扩展点

- 配置绑定类集中在 `tp-base/config/prop`，使用 `@ConfigurationProperties`：`tp.aop`、`tp.web.filter`、`tp.task`、`tp.quartz`、
  `tp.sys.mo`、`logger`、`rest.api.profiler`。  
  （证据：`tp-base/src/main/java/com/lsnju/tpbase/config/prop/*.java`）
- 默认配置模板在 `tp-base-config`，例如：
    - `tp.aop.paths-to-match=/rest/**,/rs/**`
    - `tp.web.filter.trace-header=true`
    - `tp.quartz.enable=false`
    - `rest.api.profiler.timeout=500`  
      （证据：`tp-base-config/src/main/resources/application.properties`）
- 可覆盖扩展点主要通过 `@ConditionalOnMissingBean` 暴露：
    - `TpRequestFilter`、`TpRestApiDigestFilter`
    - `tpThreadPool` / `tpForTask`
    - DAL/SAL Digest 拦截器与代理
    - REST AOP 拦截器  
      （证据：`tp-base/src/main/java/com/lsnju/tpbase/autoconfigure/TpServletFilterConfiguration.java`、
      `tp-base/src/main/java/com/lsnju/tpbase/autoconfigure/TpBaseConfiguration.java`、
      `tp-base/src/main/java/com/lsnju/tpbase/autoconfigure/TpRestApiLogConfiguration.java`）

### 设计约束与风险（结论 + 影响 + 建议）

- 结论：同名实现模块互斥（`tp-domain-*`、`tp-rs-*`）。  
  影响：易出现类冲突、运行期行为不可预期。  
  建议：统一选型；默认按 `tp-model`（`tp-domain-gson + tp-rs-simple`）执行。  
  （证据：对应模块 `BaseMo`/`BaseResp` 同 FQCN 文件）
- 结论：大量依赖为 `provided`。  
  影响：宿主项目若未补齐运行时依赖，将在启动/运行时报 `ClassNotFound`。  
  建议：通过 `tp-bom` + `spring-boot-starter-*` 完整声明宿主依赖。  
  （证据：`tp-utils/pom.xml`、`tp-rs-simple/pom.xml`、`tp-base-config/pom.xml`）
- 结论：非 `AutoConfiguration.imports` 自动发现模式。  
  影响：仅加依赖不会自动生效，遗漏 `@Enable*` 会导致能力“看似不可用”。  
  建议：主启动类显式加注解，并在接入清单做注解检查。  
  （证据：`EnableTpBase*.java`、全仓库 `AutoConfiguration.imports` 检索为空）

## 6. 快速开始（10 分钟接入）

- 前置条件
    - JDK 17。  
      （证据：`pom.xml`）
    - Spring Boot 3.5.15 体系。  
      （证据：`pom.xml`）
    - Maven 最低版本：`代码中未发现`。
- Step 1：导入 BOM（推荐）

```xml

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>com.lsnju.tp3</groupId>
            <artifactId>tp-bom</artifactId>
            <version>${latest}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>
```

（证据：`README.md`、`tp-bom/pom.xml`）

- Step 2：添加核心依赖

```xml

<dependencies>
    <dependency>
        <groupId>com.lsnju.tp3</groupId>
        <artifactId>tp-base</artifactId>
    </dependency>
</dependencies>
```

（证据：`README.md`、`tp-base/pom.xml`）

- Step 3：启动类显式启用

```java

@SpringBootApplication
@EnableTpBase
@EnableTpRestApiLog // 可选：如果需要 REST 入参/出参 AOP日志
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

（证据：`tp-base/src/main/java/com/lsnju/tpbase/annotation/EnableTpBase.java`、
`tp-base/src/main/java/com/lsnju/tpbase/annotation/EnableTpRestApiLog.java`；`@SpringBootApplication` 示例为接入最小骨架，仓库内业务启动类
`代码中未发现`）

- Step 4：最小核心配置（可运行模板）

```properties
spring.application.name=demo-tp
server.port=8080
tp.web.filter.trace-header=true
tp.web.filter.add-response=true
tp.aop.enable-rest-log=true
tp.aop.paths-to-match=/api/**,/rest/**
tp.aop.paths-to-exclude=/v3/api-docs/**,/swagger-ui/**
tp.task.enable=true
tp.quartz.enable=false
```

（证据：`tp-base-config/src/main/resources/application.properties`、
`tp-base/src/main/java/com/lsnju/tpbase/config/prop/*.java`）

## 8. FAQ 与踩坑清单

- 现象：只加 `tp-base` 依赖后能力不生效。  
  原因：本库不是 `AutoConfiguration.imports` 自动发现，需显式 `@Enable*`。  
  解决方式：在启动类添加 `@EnableTpBase`（按需再加 `@EnableTpRestApiLog` 等）。  
  （证据：`EnableTpBase.java`、`EnableTpBaseConfig.java`、`TpBaseAutoConfiguration.java`、全仓库无
  `AutoConfiguration.imports`）
- 现象：请求日志里没有 `w-req-id` 透传效果。  
  原因：`tp.web.filter.trace-header=false` 时不会使用请求头中的 `w-req-id`。  
  解决方式：开启 `tp.web.filter.trace-header=true` 并传入请求头 `w-req-id`。  
  （证据：`TpRequestFilter.java`、`RequestId.java`、`application.properties`）
- 现象：响应里没有 `X-tp-hn` / `X-tp-token`。  
  原因：`tp.web.filter.add-response=false`。  
  解决方式：开启该配置。  
  （证据：`TpRequestFilter.java`、`TpFilterConfigProperties.java`、`application.properties`）
- 现象：REST 入参/出参 AOP 日志无输出。  
  原因：未启用 `@EnableTpRestApiLog` 或 `tp.aop.enable-rest-log=false`。  
  解决方式：补齐注解并核对 `tp.aop.*` 配置。  
  （证据：`EnableTpRestApiLog.java`、`TpRestApiLogConfiguration.java`、`application.properties`）
- 现象：`/tp/mo/**` 监控接口不存在。  
  原因：`@EnableTpBase` 不包含 `TpWebApiConfiguration`；该能力在 `@EnableTpMoConfig`/`@EnableWebHomeRest` 链路。  
  解决方式：按需启用 `@EnableTpMoConfig` 或 `@EnableWebHomeRest`。  
  （证据：`EnableTpBase.java`、`EnableTpMoConfig.java`、`EnableWebHomeRest.java`、`TpWebApiConfiguration.java`）
- 现象：定时任务不执行。  
  原因：`tp.task.enable` 或 `tp.quartz.enable` 默认与开关组合不满足。`AbstractTask` 在 `tp.quartz.enable=false` 时直接
  return。  
  解决方式：按场景显式开启并配置 cron。  
  （证据：`TpTaskAutoConfiguration.java`、`TpTaskConfigProperties.java`、`AbstractTask.java`、`application.properties`）
- 现象：引入多个 `tp-domain-*` 后出现类冲突/行为异常。  
  原因：多个模块都实现同一 `com.lsnju.base.model.BaseMo`。  
  解决方式：只保留一个 domain 实现；推荐遵循 `tp-model` 默认选型。  
  （证据：各 `tp-domain-*/BaseMo.java`、`tp-model/pom.xml`）
- 现象：引入 `tp-rs-default` 与 `tp-rs-simple` 后冲突。  
  原因：两者定义相同包类（`BaseResp`、`RespEntityUtils` 等）。  
  解决方式：二选一；默认可沿用 `tp-rs-simple`。  
  （证据：`tp-rs-default` 与 `tp-rs-simple` 同名文件）
- 现象：运行时报缺少 Spring/Jackson/HTTP5 等类。  
  原因：模块大量依赖使用 `provided`。  
  解决方式：宿主项目补齐运行时依赖并统一版本（建议 BOM）。  
  （证据：`tp-utils/pom.xml`、`tp-rs-simple/pom.xml`、`tp-base-config/pom.xml`）

## 11. 结论与落地建议

- `tp-base` 是一套“显式启用、可裁剪、可覆盖”的基础库，不是零配置自动生效的 starter；团队要把“注解启用矩阵”纳入模板工程。
